# 硬件加速

[English](hardware.md) | [简体中文](hardware.zh-CN.md)

0.5.6 增加按实际能力选择的视频加速。图片及缩略图处理方式不变。解码进程仍低权限、隔离网络，只为视频任务授予必要的设备组访问权限；不修改设备权限、内核驱动或其他套件。

| 后端 | 选择方式 | 验证情况及要求 |
|---|---|---|
| Intel VAAPI | 编码器、渲染设备和私有驱动齐备时自动选择 | 已在开发 NAS 的 Intel N100 实测；iHD 驱动提取自锁定依赖 |
| AMD VAAPI | 编码器、渲染设备和可信的已安装 `radeonsi` 驱动齐备时自动选择 | 已实现，未在 AMD 硬件实测；不内置 AMD 驱动 |
| Intel QSV | 显式选择 `qsv` | 已实现；开发 NAS 当前 MFX 运行库初始化失败，该机将回退软件处理 |
| NVIDIA NVENC | FFmpeg 包含编码器且 NVIDIA 设备节点存在时自动选择 | 已实现，未在 NVIDIA 实测；当前锁定 FFmpeg **不含 NVENC**，无法激活。需兼容的 NVENC 私有 FFmpeg 构建及已安装的 NVIDIA 用户态、内核驱动 |
| 软件处理 | 自动回退或显式指定 | 原有 libx264 路径 |

编码器列表只用于筛选，不代表设备可用。初始化、编码、范围/编码校验或时长校验失败后，删除未完成输出，重试软件路径；仅将校验通过的结果提交给 Photos。保留 CPU、内存限制。

符合条件的 SDR VAAPI/QSV 任务在 GPU 内完成解码、缩放和编码。HDR 色调映射、全范围像素转换仍使用 CPU 滤镜；旋转或驱动不兼容时可能回退软件。硬件路径与 libx264 使用不同码率控制，体积、画质和速度可能不同，不能保证所有文件都更快。

可在安装目录的 `state` 中创建 root 所有、组及其他用户不可写的 `hardware.json`：

```json
{"backend":"software"}
```

允许值：`auto`（默认）、`software`、`vaapi`、`qsv`、`nvenc`。每个新视频任务读取一次。不支持的选择回退软件，不自动安装缺失驱动。日志记录 `video-backend=...` 和 `hardware-fallback=software`。

测试通过只读句柄读取原文件，输出仅暂存，处理后校验原文件指纹。一段 21.6 秒的 SDR HEVC 在 VAAPI 完整硬件缩放路径约耗时 5.6 秒；同机此前软件测试约 33 秒。这只是样本结果，并非相同画质的受控对比。全范围及有限范围黑白样本的输出亮度均为有限范围 16/235；全范围输入刻意保留 CPU 范围转换，因为实测 VPP 路径没有正确转换这些像素。

这些后端用于本项目的视频处理，不是整个系统的 AME 替代。卸载仍保留 Photos 已接收的资源。
