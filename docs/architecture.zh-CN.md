# 架构

[English](architecture.md) | [简体中文](architecture.zh-CN.md)

1. SSH 安装器校验本地构建载荷的校验值及支持的 Photos 版本，建立 root 控制的程序目录和一个 systemd 服务。
2. root 协调进程通过现有本地用户身份调用 DSM 自带的 synowebapi，不以密码登录、不保存 SID Cookie、不创建 DSM 用户、不暴露 HTTP 服务。
3. 扫描器通过 Photos 文件夹元数据解析已知缺失项目，以不跟随符号链接的目录遍历方式只读打开原件。视频的唯一输入句柄跨降权传给 FFmpeg/FFprobe 的可定位 `fd:` 协议，无需源视频副本、克隆、ACL 更改或 Btrfs。图片将同一个只读句柄传给私有 libheif reader-v1 回调桥接。解码后的 RGB/RGBA 像素逐行直接导入 MagickWand，保留主图、方向变换、位深和 ICC 配置，不产生编码中间图或原图副本。该辅助进程禁用 ImageMagick 的磁盘及映射像素缓存，仅在自身进程预加载锁定的私有 jemalloc，以满足启动时 TLS 要求，不更改全局加载器设置。
4. 子进程进入独立网络命名空间，清除附加组，切换为未使用的数值 UID/GID。no_new_privs、执行期限、内存/输出大小及线程限制约束解码。FFmpeg 从原件只读句柄流式读取，不再限制输入为 8 GiB。按时长和输出码率预留空间，解码期间每五秒检查剩余空间。
5. root 协调进程拒绝符号链接、硬链接、所有权异常及过大的输出。合格输出复制到受控暂存位置，仅授予相关 Photos 用户读取权限。
6. 再次检查打开的原件 inode 特征及相册项目，只通过 ConvertedFile 提交缺失结果，并重新读取 Photos 元数据确认成功。接口可能通过 stdout 或 outfile 返回结果，不能仅凭进程状态判断。
7. 删除临时媒体。由 root 控制的扫描游标、重试时间、有大小限制的日志及逐项目记录保留在服务目录中。

不直接修改系统 CodecPack、全局 PATH、共享加载器配置、Photos 二进制文件、原始媒体目录或 Photos 数据库。ImageMagick 和 FFmpeg 使用私有库。协调进程仍拥有高权限：解码隔离不代表对协调代码的任意更改都是安全的。

卸载仅停止、禁用本服务，删除其服务文件和自有安装目录，然后重新加载 systemd。不删除 Photos 已接收的资源；保留标准系统审计日志及用户自行保存的源码或下载文件。
