# 职责与处理规则

[English](scope.md) | [简体中文](scope.zh-CN.md)

## 当前基线

`main` 分支的 **0.6.1** 是当前主力版本，保留事件队列、只读句柄输入、预览优先、可选 GPU 和经验证的回退机制。项目仍为实验性，已验证 Intel N100 / DSM 7.4.1-90080 Update 1 / Photos 1.9.1-10928。参见[兼容性](compatibility.zh-CN.md)和[硬件状态](hardware.zh-CN.md)。文档整理不表示解码程序升级。

## 项目负责什么

在 NAS 上为受支持、已进入 Photos 索引的素材补齐预览和兼容视频。个人空间与共享空间属于设计范围，但有实际素材的共享空间生成流程尚未验收。NAS 其他目录不在范围内。

本项目是独立后台处理服务，不是完整 AME 替代品。AME 提供共享编解码能力，Photos 和 DSM 调用程序决定任务与时机；本项目采用自己的队列和保守兼容规则，不复刻全部历史判断，也不提供实时转码播放。

| 素材或状态 | 项目处理方式 |
| --- | --- |
| HEIC/HEIF/HIF，处于可识别的缺失或损坏预览状态 | 通过原文件只读句柄生成各尺寸 JPEG |
| 支持扩展名的视频，处于可识别的缺失或损坏预览状态 | 抽帧生成 JPEG；此阶段不转换整段视频 |
| 已有可用预览或 high 兼容副本 | 保留，不自动替换 |
| 缺少 high 副本，但原视频符合项目保守兼容规则 | 使用原视频，缓存判断，不虚报生成副本已就绪 |
| 缺少 high 副本，原视频不符合项目兼容规则 | 在媒体、资源限制内生成并验证 H.264/AAC MP4 |
| 不支持的格式/版本、不可用上下文、不安全或变化的源文件 | 根据现有检查跳过、延后或拒绝处理，不改写原文件 |

视频候选扩展名不限于 HEVC，包含 MOV、MP4、M4V、AVI 等容器；扩展名不是编码格式，也不保证能播放。普通 JPEG/PNG 不进入私有 HEIF 图片解码路径。保守规则可能为某些客户端本来就能播放的视频生成副本，不代表对每种手机/浏览器逐一测试。参见[现有判断](../src/photos_assistant/worker.py)和[资源限制](../README.zh-CN.md#管理与卸载)。

## 什么时候处理

- 服务首次启动或重启时，核对索引库中的历史与离线变化；发现任务不等于强制重做已接收的资源。
- 正常运行依靠文件系统事件发现新增或变化，等待文件稳定且 Photos 索引匹配，再处理对应目录。
- 预览和兼容视频是独立任务阶段，失败延迟重试；预览优先，已开始的视频任务不会被抢占中断。
- 未变化的兼容性判断使用缓存。事件溢出、目录监听丢失后恢复、手动请求可触发恢复核对，不定时反复遍历整个相册。
- 用户浏览或点击播放，不是本服务的转码触发条件；资源在后台提前准备。

详见[事件处理与恢复](events.zh-CN.md)。监听采用 Linux inotify，不是官方 Photos 上传完成回调。

## 卸载与实验边界

卸载移除本项目的服务、程序、状态和临时工作目录，保留原文件、文件名、相册目录结构，以及 Photos 已接收的资源。

旧调用分支的 15fps/Baseline 参数和独立 Intel OpenCL 运行时仅做过调查或实验，未启用于主力版本；不内置旧 AME 专有程序。0.6.1 保持最高 30fps 的现有管线及 GPU/软件回退。详见[AME 参考与色彩限制](ame-reference.zh-CN.md)。仅分发源码和现有[数据安全免责声明](../DISCLAIMER.zh-CN.md)继续适用。
