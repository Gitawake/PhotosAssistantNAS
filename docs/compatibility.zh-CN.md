# 兼容性与验证

[English](compatibility.md) | [简体中文](compatibility.zh-CN.md)

## 已验证目标

| 项目 | 测试环境 |
| --- | --- |
| CPU 架构 | x86_64，Intel N100 |
| DSM | 7.4.1-90080 Update 1 |
| Synology Photos | 1.9.1-10928 |
| NAS Python | DSM 自带 Python 3.8 |
| 安装方式 | 管理员 SSH，独立 systemd 服务 |

Photos 版本未经验证时，版本检查会主动拒绝运行。这不代表支持所有 DSM 7 或所有 x64 NAS。模拟 API 的单元测试不能证明新 Photos 版本的实际兼容性。

## 最初 SSH 实现的实机结果

- 合成 HEVC 视频从缺失状态变为 SM/M/XL 缩略图 ready、high 视频 ready；Photos 识别兼容版本为 H.264/AAC、24 FPS、三秒。
- 合成 HEIC 的三个 JPEG 缩略图尺寸均为 ready。
- 处理和卸载后，媒体原件的 SHA256 不变。
- 停止/启动正常。卸载删除程序目录、systemd 服务和自启链接；Photos 预览及兼容视频保留。
- 解码器使用不可登录的数值 UID、无附加组、有效 capabilities 为零，启用 no_new_privs，并使用不同的网络命名空间。
- 个人与共享空间元数据扫描成功；验证用共享空间为空。既有套件 INFO 校验值不变。

公开源码整理移除了未使用的会话登录及已放弃的 SPK 代码。构建流程独立使用锁定的原始依赖进行测试。重构后的源码没有在所有 NAS 配置上重新安装验证，仍属实验性项目。

## 0.5.0 直接输入验证

- 私有 FFmpeg/FFprobe 8.1.3-5 和视频库 1.5-9 在测试 NAS 上成功解析动态依赖，未使用其他套件的库路径。2026-10-21 核对时，ImageMagick 7.1.2-16 仍是上游最新可用套件。
- 实际 Photos 视频使用 `source=readonly-fd` 完成隔离预览/转码测试，测试期间不提交替换资源。
- 两秒合成 HEVC MP4 的媒体元数据位于媒体数据之后，文件以稀疏填充扩展到 9 GiB；使用 root 打开的只读句柄成功完成隔离 JPEG/H.264 生成，未创建源文件暂存副本。该测试验证随机定位及移除旧大小上限，不代表 9 GiB 实际媒体数据的吞吐性能。
- 实际 HEIC 完成隔离缩略图回归测试。发布或丢弃结果前检查原件特征。

## 0.5.1 图片直接读取验证

- 三张现有 HEIC 通过原件只读句柄生成九个 JPEG 缩略图，解码后的像素与尺寸均匹配 0.5.0（九项 PSNR 比较均为无限）；这不能证明与官方 Image Assistant 完全一致。
- 4032×3024、10 位、带旋转标记的合成 HEIC，以及透明通道合成 HEIC，输出像素均匹配旧方案。8000×6000 合成 HEIC 成功生成三种尺寸；该样本在测试 NAS 上的辅助进程峰值 RSS 约 734 MiB，其他媒体可能需要更多内存。
- 目录事件监测只看到最终三个 JPEG 的创建，没有原图副本、编码中间图或像素缓存文件；原文件身份特征保持不变。操作系统仍可能换页或交换内存。
- 完整隔离图片和视频任务均运行成功，测试未提交替换资源。损坏 HEIC 被拒绝，任务目录自动清理，原件保持不变。

## 尚未完整验证

- 手机原生 App 播放本服务输出。
- 非空共享空间实际生成；域和 LDAP 用户。
- 所有候选容器、损坏文件、HDR 或 Dolby Vision 变体。
- DSM 升级、Photos API 更改、其他 CPU 或硬件转码。
- 与 Synology Image Assistant 逐字节或感知完全一致的输出。

HEIC/HEIF/HIF 图片及代码列出的视频扩展名只是候选范围，不保证所有文件均可解码。原片质量和 HDR 保留在原始文件中；兼容副本可能为较低分辨率的 SDR。
